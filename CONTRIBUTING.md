# Участие в разработке Homer

Спасибо за интерес к проекту! Ниже — правила, чтобы вклад был быстрым
и предсказуемым.

## Кодекс

- Будьте вежливы и конструктивны.
- Обсуждайте идеи через Issues перед большими PR.
- Не коммитьте секреты (`config.yml`, `.env`, ключи, пароли).

## Среда разработки

```bash
git clone <repo> homer
cd homer
python3 -m venv .venv
source .venv/bin/activate

make install-dev
make check
```

## Что можно улучшить

* Новые драйверы БД (MySQL, MariaDB, MSSQL).
* Новые нотификаторы (Rocket.Chat, Discord, Teams).
* Метрики и трейсинг (Prometheus, OpenTelemetry).
* Асинхронные воркеры.
* Плагины из внешних пакетов.
* Улучшение документации и примеров. 

Перед крупной фичей — откройте Issue и опишите идею.

## Ветвление и коммиты

* Ветки: ```feature/<короткое_имя>```, ```fix/<короткое_имя>```, ```docs/<...>```.
* Коммиты — в стиле [Conventional Commits](https://www.conventionalcommits.org/ru/):
  * ```feat: добавить нотификатор Discord```
  * ```fix(queue): корректный retry при падении воркера```
  * ```docs: описать пример отправки письма```
  * ```test: покрыть cron-парсер случаем wrap-around```
  * ```chore: обновить ruff```

## Стиль кода

* Python 3.9+.
* Форматирование: ```make format``` (ruff format + fix).
* Линтинг: ```make lint``` (ruff + flake8).
* Типизация: ```make typecheck``` (mypy).
* Публичные API — с аннотациями типов и docstring-ами (Google style или Sphinx).
* Строки: 100 символов.
* Импорты отсортированы ruff/isort.

Пример docstring:

```pycon
def fetchval(self, sql: str,
             params: Optional[Sequence[Any]] = None,
             default: Any = None) -> Any:
    """Вернуть первое значение первой строки запроса.

    Args:
        sql: SQL-запрос с плейсхолдерами драйвера.
        params: Последовательность параметров.
        default: Значение, если запрос вернул пустой результат.

    Returns:
        Первое значение первой строки или ``default``.

    Raises:
        DBError: Если нет активного соединения.
    """
```

## Тесты

* Все новые функции — с юнит-тестами в ```tests/```.
* Используйте только SQLite и ```file```-транспорт — никаких внешних сервисов.
* Запуск: ```make test``` или ```make test-cov```.
* Фикстуры — в ```tests/conftest.py```.
* Тесты должны проходить и на Python 3.9.

## Pull Request

1. Ветка от ```main```.
2. ```make check``` проходит без ошибок.
3. Обновлён ```CHANGELOG.md``` в секции ```[Unreleased]```.
4. При необходимости — обновлена документация в ```docs/```.
5. В описании PR: что, зачем, как проверить.
6. Маленькие и сфокусированные PR — лучше больших.

## Релиз

Мейнтейнер:

1. Обновляет ```CHANGELOG.md``` (перемещает ```[Unreleased]``` в новую версию).
2. Меняет ```version``` в ```pyproject.toml``` и ```lib/__init__.py```.
3. Ставит git-tag ```vX.Y.Z```.
4. Публикует Release на GitHub.

Версии — по SemVer:

* ```MAJOR``` — несовместимые изменения API.
* ```MINOR``` — новые возможности без поломок.
* ```PATCH``` — исправления без новых фич.
