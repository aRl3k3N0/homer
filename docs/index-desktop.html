# Добавление команд

Рекомендуется создавать команды в формате ```<component>:<command_name>```

* ```<component>``` - Имя директори. Нармер, ```report```
* ```<command_name>``` - Имя команды. Наример, ```daily```

В файловой структуре будет: ```/commands/report/daily.py```

## Через генератор

```bash
homer make:command --name=report:daily \
  --description="Ежедневный отчёт" 
```

* ```--name``` Имя команды. Разрешены латинские прописные буквы, цыфры, _
* ```--description``` Описание команды


Создаст ```commands/report/daily.py``` (с ```__init__.py``` в промежуточных папках).

## Вручную

Создайте файл ```commands/hello/main.py```:

```python
"""
hello — приветствие.
"""
DESCRIPTION = "Поздороваться"

def execute(context):
    name = context['args'].get('name', 'world')
    print(f"Привет, {name}!")
    return 0
```

Ключевое:

* Функция ```execute(context)``` — обязательна.
* ```DESCRIPTION``` — необязательна, показывается в ```homer```.
* Возврат ```int``` — exit code. ```0``` / ```None``` — успех.

## Контекст ```context```

```python
{
    'config':       Config,                # config.yml
    'logger':       Logger,                # логирование
    'args':         dict,                  # аргументы CLI
    'paths':        Path,                  # Пути проекта
    'command_name': str,                   # 'report:daily'
    'commands':     dict,                  # все загруженные команды
}
```

## Имя команды из файла

| **Файл**                            | **Команда**        |
|-------------------------------------|--------------------|
| ```commands/hello.py```             | ```hello```        |
| ```commands/hello/main.py```        | ```hello```        |
| ```commands/report/daily.py```      | ```report:daily``` |
| ```commands/report/daily/main.py``` | ```report:daily``` |
| ```commands/cmdb/update.py```       | ```cmdb:update```  |

## Пример: работа с БД

```python
from lib.db import connect

def execute(context):
    config = context['config']
    logger = context['logger']

    with connect('postgres', config, prefix='databases.postgres') as db:
        rows = db.fetchall("SELECT id, name FROM users WHERE active = %s", [True])
        for r in rows:
            logger.info(f"user: {r['id']} {r['name']}", command=context['command_name'])
    return 0
```

## Пример: вызов другой команды (синхронно)

```python
from lib.queue import QueueStorage

def execute(context):
    queue = QueueStorage(['config'])
    result = queue.call('cmdb:update', user='cmdb', ver=16, timeout=300)
    if not result.ok:
        context['logger'].error(f"Ошибка: {result.error}")
        return 1
    print(result.output)
    return 0
```


# Создание проекта

Рекомендуется ничего не записывать в ```/opt/homer```, а разделять на проекты — например, по командам: ```linux```, ```dba```, ```kubernetes``` и т.д.

## Структура проекта

Для создания проекта создайте директорию в удобном для вас месте. Например, /data/dba.

Данная директория имеет следующую структуру:

```
config/     Файлы конфигурации
commands/    Ваши команды (ОБЯЗАТЕЛЬНО)
    __init__.py    Пустой файл (заглушка)
email/       Шаблоны e-mail (ОБЯЗАТЕЛЬНО)
var/         (Можно не создавать, при первом запуске создастся)
config.yml   Настройки системы (ОБЯЗАТЕЛЬНО)
```

## Переменные окружения

**Обязательно задайте**:

* ```HOMER_CONFIG``` — путь до файла конфигурации

**Опциональные**:

* ```HOMER_NO_CACHE=1``` — отключает кеш, удобен при разработке
* ```HOMER_SHOW_TIME=1``` — отображает время исполнения, удобен при отладке

##  Основной конфигурационный файл

Вы можете хранить все настройки в одном ```config.yml```, но рекомендуется разделить их и разместить в ```config/```.

Для разделения конфигурационных настроек по файлам добавьте в основной ```config.yml```:

```yml
_include:
- config/*
```

Для ускорения загрузки используете кеширование настроек:

```bash
homer config:cache
```

# Отправка уведомлений из команды

Иногда нужно отправить уведомление **не по завершении job-а**, а прямо из тела команды —
например, промежуточный статус, персональное сообщение пользователю, alert по критичной ошибке.

Есть два пути:

1. **Через `NotifyManager`** — если хотите использовать уже настроенные каналы (email, telegram, slack, mattermost, log, file, desktop).
2. **Напрямую** — если нужен специфичный формат (например, письмо по своему шаблону, конкретный webhook).

## Вариант 1: через NotifyManager (рекомендуется)

```python
from datetime import datetime
from lib.notify import NotifyManager
from lib.notify.base import NotifyEvent


def execute(context):
    config = context['config']
    logger = context['logger']
    command = context['command_name']

    # Создаём менеджер (подхватит все активные нотификаторы из config.yml)
    notify = NotifyManager(config, logger=logger, root_dir=context['root_dir'])

    # Формируем событие
    event = NotifyEvent(
        job_id=0,                                 # 0 — «не из job-а»
        command=command,
        args=context['args'],
        status='failed',                          # 'done' | 'failed' | 'canceled' | 'timeout'
        exit_code=1,
        error='БД недоступна',
        result=None,
        duration_sec=None,
        triggered_by='cli',
        attempts=1,
        max_attempts=1,
        started_at=datetime.now(),
        finished_at=datetime.now(),
    )

    # Разослать по всем активным каналам
    notify.emit(event)
    return 1
```

Кому уйдёт: всем нотификаторам, где ```event.status``` попадает в их ```on=[...]```.
Например, при ```on: [failed, timeout, canceled]``` в telegram и mattermost — уведомление уйдёт туда.

### Как отправить «успех» откуда-то

Если хотите уведомить об успешном завершении команды, но ```done``` не входит в ```on``` у ваших нотификаторов — просто добавьте ```done``` в список:

### Как отправить только в один канал

```NotifyManager``` не умеет «только telegram». Используйте нотификатор напрямую:

```python
from lib.notify.telegram_notifier import TelegramNotifier

notifier = TelegramNotifier(config)
notifier.send(event)
```

### Своё событие с произвольным текстом

Хотите не «Job #0 ... failed», а свои слова — сделайте свой лёгкий нотификатор или используйте ```TelegramNotifier```/```MattermostNotifier```/```SlackNotifier``` c готовым payload:

```python
from lib.notify.telegram_notifier import TelegramNotifier

class CustomTelegram(TelegramNotifier):
    def _format(self, event):
        return f"⚠️ <b>Важное</b>\n{event.command} упала: {event.error}"

notifier = CustomTelegram(config)
notifier.on = ['failed']              # для явного send() фильтр не нужен,
                                      # т.к. вы вызываете .send() напрямую
notifier.send(event)
```

## Как выбирать канал динамически

Пусть команда принимает ```--channel=telegram,mattermost```:

```python
from lib.notify import REGISTRY

def execute(context):
    channels = (context['args'].get('channel') or 'log').split(',')
    event = NotifyEvent(...)
    for name in channels:
        cls = REGISTRY.get(name.strip())
        if not cls:
            context['logger'].warning(f"Нет нотификатора '{name}'")
            continue
        # log требует logger, email требует root_dir — упрощённо
        try:
            cls(context['config']).send(event)
        except TypeError:
            cls(context['config'], context['logger']).send(event)
    return 0
```

## Что попадёт в уведомление

* **job_id**, **command**, **args** — что выполнялось.
* **status** — ```done``` / ```failed``` / ```canceled``` / ```timeout```.
* **exit_code**, **attempts** / **max_attempts**.
* **error** — текст ошибки (обычно с трейсбеком).
* **result** — собранный stdout команды (если выполнялась через воркер).
* **duration_sec**, **started_at**, **finished_at**.
* **triggered_by** — источник (```cron:name```, ```cli```, ```job#N```, ```shell:cmd```).

## Полезные советы

* Не отправляйте уведомления **на каждый вызов** из CLI — забьёте канал. Оставьте нотификацию для cron/queue job-ов.
* Для критичных алертов используйте ```mention_on_fail: "@channel"``` в Mattermost / ```@here``` в Slack.
* Ограничьте частоту: например, «не чаще раза в час на одну и ту же ошибку» — реализуется поверх ```NotifyManager.emit``` своей обёрткой.
* Тяжёлые ошибки (трейсбек 100 КБ) обрезаются до ~1500 символов в Telegram/Mattermost/Slack. Для полного текста используйте email с шаблоном.

# Homer

**Homer** - Изначально спроектирован для структурированного хранения и исполнения команд администраторов систем.

## Общие Возможности

Ядро системы специально спроектировано для исполнения как простых команд из директории ```commands```, так и сложных, которым необходимы дополнительные самописные библиотеки — плагины.

* **Мультиязычность**. Встроенная система i18n обеспечивает возможность перевода на разные языки.
* **Поддержка БД**. Работает с большинством популярных баз данных: Oracle, Postgres, MsSQL, MySQL, ClickHouse, Redis.
* **Каналы уведомлений**. Поддерживает различные notification-каналы: почта, SMS, Telegram, Mattermost и другие.
* **Планировщик задач**. Встроенный планировщик задач и планировщик очередей — разработчику не нужно ждать ответа от команды: достаточно получить ID очереди и вернуться к своим делам, а задача выполнится позже.
* **WebUI**. Просмотр логов прямо в браузере, выполнение консольных команд, просмотр планировщика и его задач.
* **Телеметрия и метрики**. Интеграция с Grafana и OpenTelemetry.
